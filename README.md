# secnews-omv

A self-hosted security news reader with push alerts, running on **OpenMediaVault** with Docker Compose.

[Miniflux](https://miniflux.app) collects RSS/Atom feeds (advisories, CERT bulletins, threat intel, news). For selected feeds, it publishes new entries to a self-hosted [ntfy](https://ntfy.sh) server, which pushes them to an Android phone and to a Windows PC as native toast notifications. Everything else waits in the Miniflux web UI.

Built for personal use on a home LAN. Write-up: [A self-hosted security news feed with push alerts on OpenMediaVault](https://medium.com/@catalin.fusea/a-self-hosted-security-news-feed-with-push-alerts-on-openmediavault-330f329d84ad)

```
RSS/Atom feeds ──> Miniflux ──(push only for selected feeds)──> ntfy ──> Android app
                      │                                            └──> Windows toast (ntfy CLI)
                   Postgres (internal network, no internet, not published on the host)
```

## Stack

| Component | Image | Role |
|---|---|---|
| Miniflux 2.3.3 | `miniflux/miniflux:2.3.3` | feed reader, web UI on port 8180 |
| PostgreSQL 18 | `postgres:18` | Miniflux database |
| ntfy v2.31.0 | `binwiederhier/ntfy:v2.31.0` | push server on port 8190 |

Versions were current on 2026-10-17. Check for newer releases before deploying.

## Repository layout

```

tools/push-unread.py      push already-unread entries to ntfy (one-off)
client/windows/           ntfy client config + toast script for Windows
client/linux/             ntfy client config for a Linux desktop
docs/windows-client.md    Windows client setup (Task Scheduler, toasts, DND)
```

## Security design

- **Secrets as files** (`*_FILE` variables), generated by `init-secrets.sh` with `600` permissions. The Miniflux image runs as UID 65534, so its secret files are owned by that UID.
- **Postgres on an `internal: true` network**: no internet access, no published port.
- **ntfy with `auth-default-access: deny-all`** and two least-privilege users:
  - a reader with `read-only` on `secnews*` (phone, PC);
  - a publisher (`miniflux`) with `write-only` on `secnews`, authenticating with a token.
- `no-new-privileges` on Miniflux and ntfy.
- **Feed content is treated as untrusted** on Windows: titles never go on a command line (see `docs/windows-client.md`).

## Install (on OMV, over SSH)

Requirements: Docker with Compose v2, `openssl`. Transfer the project as an archive (or `git clone`) so line endings stay LF.

```bash
git clone https://github.com/catalinfusea/secnews-omv.git secnews && cd secnews
cp .env.example .env && nano .env        # OMV_HOST = LAN IP of the OMV box
ss -tlnp | grep -E ':(8180|8190)\b'      # ports must be free
sudo ./init-secrets.sh                    # prompts for the Miniflux admin
docker compose up -d && docker compose ps # all three should become "healthy"
```

`restart: unless-stopped` brings the stack back after a reboot. If you put the project on a data disk under `/srv`, consider a systemd drop-in for Docker with `RequiresMountsFor=<mount point>` so Docker waits for the disk.

### ntfy users and tokens

```bash
docker compose exec ntfy ntfy user add <reader>
docker compose exec ntfy ntfy access <reader> 'secnews*' read-only
docker compose exec ntfy ntfy user add miniflux
docker compose exec ntfy ntfy access miniflux secnews write-only
docker compose exec ntfy ntfy token add --label=miniflux miniflux
docker compose exec ntfy ntfy token add --label=pc <reader>
docker compose exec ntfy ntfy access    # review the ACL
```

### Miniflux

1. Open `http://<OMV_HOST>:8180` and log in with the admin from `init-secrets.sh`.
2. **Settings → Import**: `feeds/secnews-feeds.opml`.
3. **Settings → Integrations → Ntfy**:
   - **tick the global "Push entries to ntfy" checkbox.** Without it, the per-feed settings are ignored and nothing is sent, with no error in the logs;
   - URL `http://ntfy`, topic `secnews`, API token = the `miniflux` token.
4. Per feed (**Edit → Ntfy**): enable push only where it matters (advisories), priority 4 or 5.

### Clients

- **Android:** ntfy app → subscribe with server `http://<OMV_HOST>:8190` (write `http://` explicitly) and topic `secnews` (**lowercase**: topics are case-sensitive). Notifications arrive only while the phone is on the home network; the 48 h cache covers the gaps.
- **Windows:** see [`docs/windows-client.md`](docs/windows-client.md).
- **Linux desktop:** `client/linux/client.yml` → `~/.config/ntfy/client.yml`, then `systemctl --user enable --now ntfy-client`. Not tested.

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| No notifications from feeds, no errors anywhere | Global "Push entries to ntfy" unchecked in Miniflux. Check `messages_published` in `docker compose logs ntfy \| grep 'Server stats'`. |
| `ntfy publish ... secnews` inside the container returns 401 | A short topic name goes to **ntfy.sh**, not to your server. Use `http://localhost/secnews`. |
| Android: `Unable to parse TLS packet header` | Server typed without `http://`; the app assumed HTTPS. |
| Android: `NullPointerException` in the parser | Wrong port (8180 is Miniflux, 8190 is ntfy). |
| Android: `User not authorized`, but curl returns 200 | Topic capitalized by the keyboard (`SecNews`); the ACL is on `secnews*`. |
| Windows: toasts only in Notification Center | Do Not Disturb is on. |
| Windows: client stops after logon, task result `0xC000013A` | Its console window was closed. Launch it with `conhost.exe --headless` (see Windows doc). |
| `push-unread.py` returns 401 from Miniflux | You used an ntfy `tk_` token; it needs a Miniflux API key. |

For details, temporarily set `NTFY_LOG_LEVEL: debug` (ntfy) or `LOG_LEVEL: debug` (Miniflux) in the compose file.

## Pushing already-unread entries

Miniflux only pushes entries it fetches *after* the integration is enabled. To push what's already unread:

```bash
cd tools
./push-unread.py --list-categories
./push-unread.py --category-id <ID>          # dry run
./push-unread.py --category-id <ID> --send   # max 10 by default, --limit up to 50
```

It asks for the Miniflux API key and the ntfy publisher token interactively. It does not mark entries as read.

## Known limitations

- **Plain HTTP on the LAN**: tokens and passwords travel in clear text. HTTPS with a local CA is on the to-do list.
- `INTEGRATION_ALLOW_PRIVATE_NETWORKS=1` lets any Miniflux integration reach the LAN; acceptable for a single-user instance.
- ntfy runs as root inside its container (with `no-new-privileges`).
- `conhost.exe --headless`, used to start the Windows client without a window, is not officially documented by Microsoft.
